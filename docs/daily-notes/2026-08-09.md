## Cost-provenance fail-closed fix

The August 8 cost gate correctly rejected missing or zero transaction costs, but it trusted any positive `bps_per_side` value. A stale or partially migrated validation report could therefore stamp `25` while declaring a gross basis, omitting the actual round-trip charge, or failing to say that R and win/loss labels were recomputed. If its metrics otherwise passed, the audit would accept that decorative stamp as cost-adjusted evidence.

Hardened `scanner/edge/audit.py` so `costs_charged` now requires all of the following:

- a positive per-side cost;
- `basis=net_of_costs`;
- a finite round-trip percentage exactly consistent with the per-side basis;
- explicit coverage of returns, R multiples, and win/loss labels.

Malformed, inconsistent, and partial cost provenance now blocks both readiness evidence routes. The audit exposes each sub-check for operator diagnosis. Updated regression fixtures to the full production report contract and documented the stricter boundary in `scanner/README.md`.
