## Candidate-level live authorization fix

The readiness audit correctly required an execution-ready promoted Edge candidate before returning `paper_trade_only`, but `live` mode was a separate strict Potter/Empty Space scan. Once the global preflight passed, that path could send a Telegram alert for a different ticker or a direction that had never earned Edge promotion. It also did not reapply the audit's consolidated-equity and execution-grade-options checks to the exact fresh alert candidate. This violated the design rule that every live signal itself must clear the Edge threshold, analog expectancy, direction evidence, data quality, and liquidity gates.

Hardened `scanner/main.py` and the shared execution check in `scanner/edge/audit.py`:

- preflight now fails closed unless a `paper_trade_only` audit names a promotable direction and at least one execution-ready promoted candidate;
- immediately before any live Telegram send, the exact current ticker/direction is rescored against the current retrieval index with its current options contract;
- the fresh setup must receive `recommendation=promote`, belong to a validation-supported direction, and pass the same capital-grade equity/options check used by the audit;
- a failure is journaled as a pending counterfactual at `stage_failed=edge_promotion`, including Edge score and blocking reasons, and no message is sent.

Dry-run and research collection behavior is unchanged. Updated `scanner/README.md` to document the candidate-level gate.
