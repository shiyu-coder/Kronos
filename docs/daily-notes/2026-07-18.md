## Bug fixed: no-op adaptive changes reset cooldown

Friday correctly raised `DOCTRINE_V2_SCORE_BASELINE` from 70 to 75. On the next run, however, the adaptive policy would select 75 again, label the equal value an auto-applicable improvement, rewrite `overrides.json`, and refresh `_meta.last_auto_change_at` even though no parameter changed.

That is not harmless bookkeeping: `last_auto_change_at` gates the conservative cooldown for a future evidence-backed research-threshold loosening. A daily no-op Doctrine write could therefore postpone loosening indefinitely and starve the research journal.

Changes:

- Supported automatic tightenings must now be strictly higher than the active threshold/baseline.
- A supported current value reports an explicit hold with no proposed override.
- The apply path independently strips overrides equal to live configuration, preventing stale or combined recommendations from mutating cooldown state.
- Added regressions for research-threshold holds, Doctrine-baseline holds, and byte-stable no-op application.
