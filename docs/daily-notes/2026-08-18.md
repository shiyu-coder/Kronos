## False punchback-reclaim bug

The experiment forced a closer audit of `scanner/strategy/potter_doctrine.py`.
Doctrine v2 called a setup `reclaim` whenever either of the two bars before the
current break touched the control. Those are normally consolidation bars; no
earlier breakout had occurred, so the touch cannot be a post-breakout retest.
The stronger 30-point reclaim award therefore described an event the detector
had not observed.

A red regression reproduced the false `reclaim`. The detector now requires an
ordered sequence: an earlier close outside control, then a later control-level
touch with a continuation-side close. Otherwise a current break is
`fresh_breakout`. A read-only recomputation of all 11,028 saved rows changed
6,539 old `reclaim` labels to `fresh_breakout`; only 14 retained a valid
ordered reclaim. Corrected doctrine scores fell on 6,550 rows, never rose, and
declined by 7.13 points on average.

Corrected doctrine records carry evidence version 2 and Edge feature version
4. Adaptive policy excludes legacy unversioned doctrine scores instead of
